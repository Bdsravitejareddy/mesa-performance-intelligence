# Public research adapters

The server-only adapter supports Tavily and Brave. Set `PUBLIC_SEARCH_PROVIDER` to `tavily` or `brave` and supply `TAVILY_API_KEY` or `BRAVE_API_KEY` in the deployment secret manager. No key is required for unrelated application features. Missing or invalid provider selection and missing credentials produce explicit readiness states. No live credentials or provider calls were used to verify this implementation.

Create one `createResearchSession()` per user-initiated discovery, pass it to `createSearchProvider({ session })`, then call `searchPublicWeb(query, provider)`. Reuse that session for all searches and page fetches in that discovery; never create a new session inside a query/page loop. A discovery has at most eight distinct normalized public queries, five unique results per query, twelve distinct page URLs including redirects, a 30-second total lifetime, an eight-second request timeout, and a 2 MiB response limit. At most three requests run concurrently and requests to the same host start at least one second apart, including provider APIs, robots and redirects. Queue time counts against the discovery deadline. Concurrent duplicate queries/pages share work, including failed attempts. Redirects from the fixed provider API endpoints fail; credentials are transmitted only in authentication headers. Provider HTTP bodies and errors are never logged or returned.

The `SearchQuery` union accepts explicit role/location/organization or professional-topic fields, not arbitrary raw queries or context. Runtime validation rejects unknown fields, long values, email addresses, URLs, numeric identifiers, common private-data labels, and known provider credentials. This validation cannot determine whether otherwise ordinary words are private. Callers must construct fields from public research subjects only. Never derive a search from a resume, marks, submissions, course files, private contact notes, or student identity, and never pass private context into these adapters. No module here imports private student data.

Every result carries `evidence: "discovery-only"`. Titles, snippets, and provider-reported dates remain unverified, and Tavily answer/raw-content fields are not requested or used. HTTPS links are normalized and deduplicated; LinkedIn, `lnkd.in`, Facebook, Instagram, X/Twitter, credentials in URLs, IP literals, and nonstandard ports are excluded. Passing these discovery checks does not authorize page fetching or establish a claim. A directly supporting permitted public page must be fetched before a role or person claim becomes evidence.

## Retrieval boundary

Call `fetchPublicSource(url, { session, approvedSources })` only on the Node server after a domain/terms review. The library does not add routes or browser integration. Default approval is empty: callers must explicitly supply exact hostnames with approved source classes. Dependency overrides are for trusted server tests and must never be supplied by request input. The implementation enforces these boundaries together:

- Approve exact hostnames after reviewing site terms and source class: employer careers, organization/team pages, government sources, conference speaker pages, or professional publications. Approval is a caller responsibility; a source-class label does not establish terms permission. Source classes do not override robots rules, access controls, or domain restrictions. LinkedIn and the denied social domains remain prohibited. Login/auth/account/admin/API paths are blocked.
- Require HTTPS on port 443, reject URL credentials/IP literals, and validate every resolved IP before every connection and redirect, including after robots retrieval. Reject mixed public/private answers, private, loopback, link-local, reserved, multicast, documentation, and address-translation ranges. IPv6 permits only conservative global-unicast ranges. Each actual connection uses the validated address while preserving the original hostname for TLS SNI and certificate verification.
- Use Node `https.request` with a fixed validated lookup result, a pinned address family, a fresh connection (`agent: false`), and certificate verification enabled. No browser/Edge fallback, implicit proxy, or ordinary page `fetch` is used. Unsupported runtimes cannot use these Node-only modules.
- Check robots rules before every permitted path with `MesaintelligenceResearch/1.0 (public career research; robots compliant)`. Longest matching rules, equally specific Allow, user-agent groups, wildcards/end anchors, and encoded path octets are supported. A missing robots file (404/410) permits crawling; other errors, unsupported directives such as crawl-delay, malformed rules, or rules larger than 512 KiB fail closed. No retry around restrictions. Robots and page redirects recheck URL/domain/DNS rules and are limited to four hops; each redirected page gets its own robots check.
- Accept only HTML/plain text; request identity encoding and reject compressed responses. Enforce the shared limits above while consuming the full response body. Never execute scripts or issue secondary resource requests. HTML extraction scans linearly, removes scripts/styles/comments/head content and uses common named/numeric entities; plain text remains literal. Dynamic-only pages and empty extractions return unavailable. This is conservative static text extraction, not a browser rendering or full HTML5 DOM parser.
- Return fetched title/text/page metadata date, final canonical retrieval URL, SHA-256 response-content hash, and retrieval time, or typed blocked/unavailable status. HTML canonical-link tags cannot redirect provenance. Treat fetched text and dates as untrusted data; fetching alone does not prove that a specific claim is supported.

The existing Next.js 16 server/client boundary and Edge runtime documentation were read before implementing these server-only modules. No routes or runtime settings changed.

Provider contracts were checked against [Tavily Search](https://docs.tavily.com/documentation/api-reference/endpoint/search) and [Brave Web Search](https://api-dashboard.search.brave.com/api-reference/web/search/post), including [Brave authentication](https://api-dashboard.search.brave.com/documentation/guides/authentication).
